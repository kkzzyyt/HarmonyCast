# Windows 投屏黑屏排查

设备信息和 HiLog 能读取时，说明基础 HDC 通道可用。投屏仍需完成设备采屏程序传输与启动、视频端口映射、视频握手和解码，任何一段失败都可能没有画面。

## 不同 Windows 环境

| 环境 | 处理方式 |
| --- | --- |
| Windows 10 22H2 / Windows 11 x64 | 使用普通版，视频优先硬件解码，持续失败后切换 CPU，再尝试兼容截图 |
| 远程桌面 / RemoteFX | 结合远程会话标志与当前会话 ID 检测，优先使用软件模式 |
| 虚拟机 / 无可用显卡驱动 | 硬件初始化失败时使用 CPU；可直接从开始菜单选择软件渲染模式 |
| 核显 / 独显 / 驱动重置 | 解码或硬件帧传输持续失败后，在解码调用结束后安全重建 CPU 解码器，重放参数并等待关键帧 |
| 上次异常退出 | 在创建图形窗口前读取持久崩溃标记，软件模式恢复；标记路径支持中文 Windows 用户目录 |
| 中文用户名 / 安装路径含空格 | HDC、日志与巡检共用进程工作目录、依赖搜索路径及无控制台配置，参数直接传递，不经过 cmd 拆分 |
| 企业代理 / PAC / VPN | 本机视频和控制通道明确直连 `127.0.0.1`，避免被系统代理转发；在线更新继续使用自己的网络配置 |
| 双屏不同缩放比例 | 切换显示器或 DPI 变化时清理投屏缩放缓存，通知后台按新像素比例准备画面，保留原始视频像素 |
| Windows ARM64 | 当前仅提供 x64 Windows 包，依赖系统的 x64 模拟，需在目标电脑验证，尚未提供原生 Windows ARM64 包 |
| Windows Server 2012 / 2012 R2 x64 | 使用独立的 Server2012 兼容版，CPU 解码、Qt5 与专用运行库，不能靠软件参数把普通 Qt6 包变成兼容包 |
| 较早的 Windows 10、Windows 7/8、32 位系统 | 普通包的当前 FFmpeg 上游最低保证 Win10 22H2；这些环境不能直接承诺兼容，需要单独构建或验证，32 位和 Win7/8 不在当前支持范围 |

普通包当前采用的 [FFmpeg 构建说明](https://github.com/FFmpeg-Builds/FFmpeg-Builds/blob/master/README.md) 将最低保证版本列为 Windows 10 22H2。[微软的远程桌面检测说明](https://learn.microsoft.com/en-us/windows/win32/termserv/detecting-the-terminal-services-environment) 指出，部分 RemoteFX 会话不能只依赖 `SM_REMOTESESSION` 判断。

布局已用 Qt Windows 样式及 125%、150%、200% 缩放验证设备弹窗、日志开关、滚动和命令输入。该验证在 macOS 上运行，不能代替目标 Windows 的真实字体、输入法和驱动测试。

修复后的连接流程会在没有首帧或画面停止返回时尝试兼容截图，并在兼容截图也没有返回时停止，保留具体原因。TCP 连接成功只表示视频通道已连接，收到可显示画面后才更新分辨率状态。

编码视频超时会先请求一次 CPU 解码重建，缓存 SPS/PPS 并等待新的关键帧恢复。仍没有画面才降级截图，避免把显卡兼容问题直接当成设备断线。

| 提示 | 需要检查的环节 |
| --- | --- |
| 缺少设备采屏程序 | 是否使用完整安装包，`resources/capture` 下是否有匹配设备架构的程序 |
| 采屏程序传输失败 | 提示中的 HDC 原始错误、本机程序文件路径及设备写入权限 |
| 采屏程序未能启动 | 设备返回的执行、系统库或权限错误；启动输出保存在设备 `/data/local/tmp/harmonycast_capture_start.log` |
| 视频通道已连接，但一直未收到可显示的首帧 | 采屏服务是否实际产生画面、视频数据是否能被解码 |
| 缺少 JPEG 图像插件 | 使用完整安装包，确认 Qt 图像插件部署完整 |
| 兼容截图未返回画面 | 设备截图权限、HDC 文件传输及日志中的具体错误 |

设备缺少 `libnative_display_manager.so` 或 `OH_AVScreenCapture_*` 符号时，表示设备系统与随包原生采屏程序不兼容。界面显示兼容模式切换提示，底层启动错误保留在诊断日志；第一张兼容截图返回后才提示“已启用兼容截图投屏”。截图模式的帧率取决于设备截图和文件传输耗时。

兼容截图会在每次采集和接收前移除旧图片，并检查 HDC 输出中的失败信息，避免把旧图片当成新画面。设备不支持截图缩放参数时会重试原始尺寸；命令缺失或截图权限被拒绝时直接给出原因。其他失败继续重试，最终超时提示会包含最近的失败阶段，例如截图传输失败或图片不完整。

Windows 的软件模式现在同时关闭 Qt 硬件渲染和 FFmpeg 硬件视频解码。修复版可用随包的 `HarmonyCast-SoftwareRendering.cmd`，或给 `HarmonyCast.exe` 添加 `--software-rendering` 参数。旧实现只设置 Qt 软件渲染，仍可能启用 D3D11 视频解码。

需要定位故障电脑的具体原因时，在该电脑的设置中导出诊断包。投屏日志会记录当前解码器选择、各阶段状态及是否收到首帧。提供 Windows 版本、设备型号、相同设备在另一台电脑上的表现和失败时间，便于对照记录。

本地回归使用模拟 HDC、静默 TCP 连接和本地视频帧，覆盖首帧超时、画面停滞、启动失败和停止后的清理。Windows 显卡驱动及设备采屏权限仍需在故障电脑验证。
