# HarmonyCast 后续发展规划

更新日期：2026-10-28  
基线：当前 v2.2.1 工作区实现，包含本轮性能与内存优化  
文档状态：规划草案，新增能力尚未实施；阶段编号表示推进顺序，版本号为建议

## 1. 产品方向与目标

将 HarmonyCast 建设为面向 OpenHarmony / 鸿蒙设备的桌面调试与维护工作台，让开发、测试和现场维护人员在一个窗口内完成：

**连接设备 → 安装与启动应用 → 投屏操作 → 查看日志与请求 → 复现问题 → 保存故障证据。**

后续发展的重点是减少重复命令、缩短问题定位路径，并让长时间使用保持稳定。已有投屏、触控、截图、日志、设备控制和兼容回退是持续维护的基础能力。

### 1.1 主要使用场景

| 用户 | 常见任务 | 期望结果 |
| --- | --- | --- |
| 应用开发人员 | 安装 HAP、启动应用、查看 HiLog / WebView、复现问题 | 快速完成一次构建后的验证 |
| 测试人员 | 重复执行操作、录制现象、标记异常、提交问题资料 | 复现步骤和故障证据完整、可追溯 |
| 现场维护人员 | 连接终端、检查应用与网络、拉取日志、导出设备信息 | 少输入命令，清楚知道操作对象与执行结果 |
| 多设备调试人员 | 辨认设备、切换目标、比较应用版本和运行表现 | 操作目标明确，设备间数据不会混淆 |

### 1.2 发展原则

1. **主体功能持续可用**：新增模块逐步接入，原有操作入口与兼容路径保留到替代路径验收通过。
2. **先完成单设备体验**：先完善连接、应用、文件、日志和证据导出，再扩展多设备并行操作。
3. **能力以设备探测为准**：按系统、架构、权限和实际命令结果决定可用功能，不统一假设所有设备支持同一接口。
4. **任务结果可判断**：长操作有进度、超时、取消和最终结果；取消需要真正传递到底层任务。
5. **性能有预算**：采集、显示、历史保存分开管理，新增功能明确 CPU、内存、磁盘和线程开销。
6. **状态真实可追溯**：查询失败显示未知或失败原因；推断值与设备实际返回值分别标注。

## 4. M0：稳定性与交互基础

### 4.1 工作范围

- 完成 BASE-01 至 BASE-06，建立一致的连接、任务、采集与显示状态。
- 增加任务管理基础：任务 ID、目标设备、进度、超时、取消、结果和历史。
- 完善断线、未授权、端口占用、服务启动失败、权限不足等提示，提供对应重试入口。
- 整理工作台工具栏：常用操作直接可见，显示设置和诊断操作按任务分组。
- 记住窗口大小、布局、分屏比例、字号和筛选偏好，并提供恢复默认入口。
- 补齐 macOS / Windows 的启动、连接、投屏、截图、日志与导出验证。

### 4.2 阶段验收

1. 取消长命令后，任务确实停止，不再继续更新成成功状态。
2. 仅日志模式能独立采集；暂停显示与停止采集的含义、按钮状态一致。
3. 快速切换设备、画质或页面时，旧会话的数据不会写入新会话。
4. 自动投屏设置在重新连接、进入工作台和手动停止后均有可重复验证的行为。
5. 首次使用、窄窗口、无设备和连接失败场景都能完成下一步操作。
6. 形成实际测试过的设备 / 系统 / 架构 / 平台清单，记录通过与未验证项目。

### 5.1 使用流程

**选择已备注设备 → 拖入 HAP → 查看安装结果 → 启动目标应用 → 自动定位该应用日志。**

文件工具应能直接进入常用日志目录，并把拉取的文件定位到电脑目录，减少重复输入远程路径。

### 5.2 边界与依赖

- 文件浏览首版聚焦查看和收发，批量删除、系统目录编辑放到后续明确范围内。
- 通用应用管理保留现有业务应用快捷操作，避免专用终端工作流退化。
- 进度值必须来自实际传输或安装阶段；无法取得百分比时显示阶段与已耗时。
- 依赖 M0 的任务取消、目标隔离与连接状态管理。

| DBG-07 | 文本发送 | 电脑端输入并发送文字、基本快捷键说明 | 在明确支持的输入场景下验证中文、英文和特殊字符；不支持时提示原因 |

### 6.1 录屏的推进顺序

1. 先验证复用现有 H.264 数据保存视频的方案，评估编码参数、关键帧、时间戳和文件封装。
2. 补齐停止、断线、空间不足、文件写入失败的恢复流程。
3. 对 RGBA 和截图兼容模式单独评估编码开销，通过测试后再启用。
4. 光标 / 触控标记、水印、麦克风或设备音频作为独立增强项，按需求推进。

### 6.2 故障资料包的建议结构

```text
case-<时间>-<设备标识>/
  manifest.json          # 会话、设备、应用、采集结果与文件索引
  report.md              # 问题描述、复现步骤、人工标记与环境信息
  screenshots/           # 原尺寸截图
  recordings/            # 可选录屏
  logs/                  # HiLog、应用日志与采集工具日志
  network/               # 可选请求记录或 HAR
  metrics/               # 后续接入的资源采样数据
```

导出前可预览资料范围，并对请求头、请求体和日志中的敏感字段提供可选脱敏。采集和资料管理以本地文件为主。

## 7. M3：性能与网络排查

| 功能 ID | 功能 | 首次交付范围 | 验收重点 |
| --- | --- | --- | --- |
| OBS-01 | 设备与应用资源曲线 | CPU、内存、存储、进程存活，按设备能力提供 | 标明采样时间、单位与数据来源；采样频率可设置；缺失指标显示不支持 |
| OBS-02 | 投屏运行指标 | 实际接收 / 解码 / 显示帧率、流量、待处理数据量、解码方式 | 各指标定义清楚；请求 60FPS 与实际显示 FPS 分开；开关面板开销可测 |
| OBS-03 | 卡顿与异常记录 | 手工标记、进程退出提示、错误日志计数、相关时间段截取 | 能从一个事件跳到附近日志、请求和资源采样；提示规则可配置 |
| NET-01 | 网络检测工具 | 网卡 / IP 查看、目标端口探测、按设备能力提供连通性与 DNS 检测 | 区分电脑侧与设备侧结果；检测有超时和取消；不把单项失败直接解释为断网 |
| NET-02 | Network 会话增强 | HAR 导出、请求完成 / 失败状态、请求大小、耗时分解候选 | 导出可被选定工具读取；缺失时序字段明确标注，不伪造耗时 |
| OBS-04 | 故障时间线 | 将人工标记、日志异常、请求失败、截图与资源曲线关联 | 标注时间来源与采样间隔；不同设备时间未校准时说明偏差 |

资源监控与异常检测首先采用低频、可关闭的采样方式。全设备抓包、完整系统调用跟踪、持续高频性能剖析需要额外能力验证，作为独立专题评估。

界面细节包括：统一控件高度与间距、可折叠筛选区、窄窗口适配、键盘焦点、跨平台快捷键提示、可读的状态颜色与文字，以及截图成功后的轻量反馈。

## 10. 技术演进大纲

### 10.1 模块职责

| 层次 | 建议职责 | 对应演进方向 |
| --- | --- | --- |
| 界面 | 页面、操作入口、展示与交互反馈 | 将应用、文件、日志和网络面板逐步从 MainWindow 拆分 |
| 设备会话 | 设备身份、连接、能力、会话 ID 与服务生命周期 | 支撑日志独立采集及后续多设备 |
| 任务执行 | 命令、进程句柄、队列、进度、取消、超时与结果 | 统一安装、文件收发、诊断与命令中断 |
| 数据与存储 | 有界缓存、会话索引、临时文件、导出与清理 | 在线显示和长期保存分开管理 |
| 协议与平台适配 | HDC、视频流、WebView、系统差异 | 以能力探测和回退维护兼容性 |

每次拆分围绕一个功能形成小步迁移，并以现有行为回归作为完成条件。持续复用已有 HdcClient、StreamSession、HiLogSession、WebViewDebugger 与视频处理基础。

### 10.2 建议的依赖顺序

```text
设备身份与能力 ──→ 会话隔离 ──→ 多设备
任务管理与取消 ──→ 安装 / 文件传输 ──→ 步骤编排
日志长期存储 ──→ 离线查看 / 标记 ──→ 故障会话
WebView 目标选择 ──→ 会话级请求记录 ──→ HAR / 时间线
投屏真机基线 ──→ 录屏 ──→ GPU / 编码与控制协议专题
资源采样 ──→ 趋势曲线 ──→ 异常关联
```

### 10.3 需要专题验证的能力

- GPU 直接显示：分平台验证硬件表面、生命周期、缩放 / 旋转与软件回退，先提供可切换试验路径。
- 设备端分辨率调整：验证原画、各档位、横竖屏和触控坐标，不以改档位名称代替实际生效验证。
- 持久化输入控制：验证命令顺序、长按 / 滑动、中文输入、断线恢复与旧设备回退。
- 录屏封装：验证不同流模式、时间戳、文件结束与异常退出恢复。

## 11. 性能、内存与质量门槛

以下为后续计划验收项，尚未代表已经完成真机验证。

| 维度 | 建议验收方式 |
| --- | --- |
| 主流程 | USB / 网络连接、投屏、触控、截图、日志、安装与导出形成固定回归清单 |
| 长期运行 | 代表性设备连续投屏并采集日志至少 2 小时，观察 CPU、RSS、队列和临时文件趋势 |
| 反复启停 | 建议至少 50 次启停及 20 次断线 / 重连；退出后检查进程、端口与临时文件清理 |
| 性能比较 | 在相同主机、设备、分辨率、流模式和日志负载下与上一稳定版本比较，保留原始数据 |
| 内存与磁盘 | 标明各缓存与历史文件预算；展示旧数据淘汰和剩余磁盘状态；当前查看内容可完整导出 |
| 操作响应 | 记录关键操作的耗时分布与失败率，长任务不阻塞界面；阈值在真机基线建立后确定 |
| 兼容性 | 分平台、系统、架构、连接方式和采集模式记录通过 / 失败 / 未验证 |
| 自动化验证 | 核心逻辑与协议回归、后台生命周期、取消与超时、实际 GUI 冒烟、适用平台的内存检查 |
| 发布结果 | 安装、升级、首次启动、依赖完整性与功能回归通过后再发布 |

现有性能与内存优化、测试命令及局部基准见 [performance.md](performance.md)。局部基准结果不替代真机端到端帧率、控制延迟或长期稳定性结果。

## 12. 兼容性与数据管理

- 建立设备能力档案，记录型号、系统、架构、连接方式、权限与已验证能力，允许刷新探测结果。
- 配置增加版本字段与迁移逻辑；升级前后的设备备注、收藏、历史记录保持可读。
- 会话文件定义版本、编码、时间来源和采集结果；断开设备后仍可查看已保存的资料。
- 缓存、长期会话和导出目录分别配置，临时文件自动清理，长期资料有明确保留策略。
- 现有 ICU / 看门狗等专用功能按能力呈现，通用设备不会出现无法解释的操作入口。
- 新协议和新渲染路径逐设备、逐平台启用，回退路径在验收前持续保留。

## 13. 版本与交付管理

### 13.1 每项功能交付时包含

1. 用户场景、入口、范围与不支持情况。
2. 状态流转、失败结果与取消规则。
3. 设备 / 平台依赖与测试设备列表。
4. 可执行的验收条目与回归结果。
5. 对性能、内存、磁盘与配置迁移的影响记录。
6. 使用说明、变更记录与可评审的构建产物。

### 13.2 发布顺序

**完成实现与测试 → 真机验收 → 试用构建 → 修复反馈 → 更新文档与兼容矩阵 → 稳定发布。**

版本号由一个来源生成并同步到窗口、侧栏、更新检查与安装包。平台构建应分别运行适用的测试；某平台尚未验收时，发布说明如实标注。
